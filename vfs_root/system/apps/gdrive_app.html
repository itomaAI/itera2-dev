To share one VFS across several devices, every device must choose the same folder. By default each device creates a new folder named Itera OS, so if you leave it alone they end up on different folders and nothing is shared.

Changing the folder breaks the correspondence with the anchor, so the sync state is reset. On the first cycle after the reset, what is on the remote comes down as stubs, and what exists only locally is uploaded (nothing is deleted on either side).

📁 What is synced

Where the Drive folder is mapped inside the VFS. Leave it empty to sync the whole VFS root. Changing it breaks the correspondence with the anchor, so the sync state is reset when you save.

Matched by prefix on path boundaries. trash does not match trashcan/.

Fixed rules (cannot be changed)
Always excluded: system/credentials, system/temp, system/logs, trash
Synced under system/: system/config, system/registry, system/themes (nothing else under system/ is synced)

To keep credentials from leaking, this allowlist / denylist cannot be loosened from the app. You can only add further exclusions.

⚠️ Dangerous actions

Reset the sync state

Deletes the anchor and the index. No file is removed, locally or in Drive. Use it to recover when syncing goes wrong. On the next start it is rebuilt with the remote as the truth.

Delete the sync folder in Drive

Permanently deletes the folder in Drive and everything in it (it does not go to the trash). The local VFS is kept.

Order of the steps (fixed for safety)

1. stop the daemon → 2. delete in Drive → 3. clear the anchor, the index and the folderId

If this order is not kept, the next sync cycle reads it as "every file was deleted on the remote" and permanently deletes the local copies.
