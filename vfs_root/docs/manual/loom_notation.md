# Loom 記法 v0.4

2026-08-26。**Loom のファイル形式の正**（`data/apps/loom/*.md`）。
人向けの使い方は `docs/manual/loom.md`、AI 側の動き方は `memory/rules/loom.md`。

> **v0.4** —— **プロジェクトの総括を 5 枠にした**（§4。**意図・経緯**を足した）。
> 総括は親の履歴という**文脈の無い場所**で読まれるので、決定だけ運ぶと**決定の範囲**（どういう問いの下で、
> 何を観測し、何を制約として決めたか）が親に届かない。タスクのレポートは 3 枠のまま。
> あわせて **`## 意図` が少しずつ変わること**を記法に入れた（§2「意図」・§5・§7）—— **読み替え**は積み、
> 読み替えで無理なら**継承**。**古びには 2 方向ある**（源が伸びる／観点が動く）。

---

## 0. 原則

* **1 ノード 1 ファイル。ファイルが唯一の正。**アプリが無くても読み書きできる
* **追記が既定。**書き換えてよいのは次の 3 つだけ ——
  front matter の値 ／ `## 成果物` の一覧 ／ **`## 文脈`（写しなので畳み直してよい）**
* **`## 履歴` と `## 進捗` は絶対に書き換えない。**唯一の正であり、腐りを検出できないため
* **`## 意図` も書き換えない。**変わったら**積む**（§2「意図」）
* **すべての追記行は日時から始まる**（JST）。日時は**枠の終端**でもある（次の日時つきの行、または次の見出しで閉じる）
  * **例外は「枠の中への追記」**（§4）。日時から始めると枠が閉じてしまい中に入らないので、
    `- **追記 <日時> <名前>**: 本文` と書く（先頭が `- **` なので終端と読まれない）
* **辺の正は 1 箇所（子の front matter）。**親の履歴に入る「分岐: …」は**辺の複製ではなく出来事の記録**

## 1. front matter

| キー | project | task | 値 |
| :-- | :-- | :-- | :-- |
| `id` | ● | ● | `P-0001` / `T-0001`（**接頭辞で型が見える**。本文中の参照でも型が分かる） |
| `kind` | ● | ● | `project` / `task` |
| `title` | ● | ● | |
| `status` | ● | ● | 下記 |
| `created` | ● | ● | ISO8601（**UTC**。アプリは `2026-08-24T00:50:00.000Z` の形で書く） |
| `parent` | ● | ● | 親子辺。**P→P / P→T / T→T の 3 つだけ。T→P は無い** |
| `supersedes` | ● | | 前後辺。継承したとき、後継が持つ |
| `refs` | ● | ● | 参照ファイル。**タスクの refs は所属プロジェクトの refs の部分集合** |
| `priority` | | ● | `high` / `normal` / `low` |
| `scheduled` | | ● | `YYYY-MM-DD` |

**記法に無いキーを書いてもよい。** アプリは知らないキーをそのまま書き戻す（順は既知のキーの後ろ）。
ただし**アプリは知らないキーを読みも使いもしない**ので、意味を持たせるなら記法に載せること。

**status**

* project … `live`（生きている）／ `frozen`（凍結）／ `superseded`（継承済み）／ `abandoned`（放棄）
* task … `inbox` → `todo` → `doing` → `review` → `done`。ほかに `blocked` / `paused` / `dropped`

**手番はタスクだけが持つ**（status から導く）。プロジェクトは手番を持たない。

## 2. 節

* **project**: `## 意図` `## 文脈` `## 履歴` `## 成果物`
* **task**: `## 依頼` `## 計画` `## 追加要望` `## 進捗` `## 確認事項` `## 成果物`

見出しは変えない（機械が追記先を見つける目印）。

### 意図（project のみ）— 原点と読み替え

意図は 3 つの役を負う: **畳むときの観点**（文脈生成・総括）／**親が分岐時に記録した「なぜこの枝があるか」＝範囲**／
終端の型（満たされない＝プロジェクト）。**意図は少しずつ変わる。** 変わり方を記法で受ける。

```
## 意図

（分岐時に置いた意図。書き換えない）

- 2026-08-26 11:00 山内 読み替え: 〈新しい読み〉（理由。総括 2026-08-26 10:40 より。文脈は据え置き: 理由）
```

* **最初の塊が原点。書き換えない。** 変わったら下に日時つきの行を**積む**（`読み替え:` で始める）。
  **現在の意図＝最後の行**（無ければ原点）
* **読み替えとは、原点がまだ新しい読みを含んでいること**（狭まった・広がった・研がれた）。
  **原点を置き換えなければならない**なら、それは読み替えではなく**継承**（§7）
* **気づくのは畳む者、置くのは人。** 読み替わりは畳んでいるとき（総括の「意図」枠）に見つかる。
  畳む者はそこに**観測として**書き、板の外でも伝える。`## 意図` へ行を積むのは**人の一手**
  （代筆するときは名前を人にする）
* **読み替えたら文脈の再生成を検討する**（観点が動いたので写しが古びうる）。**必須ではない** ——
  読み替えは前進的に起こるので、文脈が既に新しい読みで畳まれていることがある。
  据え置くならその旨と理由を読み替えの行に添え、畳み直すなら §5 のとおり `## 履歴` に 1 行残す
* **親には総括で届く**（§4 の「意図」枠）。親の履歴の `分岐:` 行は書き換えない

## 3. 追記行

```
- YYYY-MM-DD HH:MM 名前: 本文
```

**出来事は決まった動詞で始める。**（機械が拾い、画面が印を付ける）

| 出来事 | 書く場所 | 形 |
| :-- | :-- | :-- |
| 分岐 | 親 P の履歴 | `分岐: P-0007「題」` |
| 継承 | 後継 P の履歴 | `継承: P-0002「題」を継いだ` |
| 〃 | 前任 P の履歴 | `継承: P-0009「題」へ継いだ（凍結）` |
| 起票 | P の履歴 | `起票: T-0128「題」` |
| 分解 | 親 T の進捗 | `分解: T-0129「題」` |
| 完了 | P の履歴 ／ 親 T の進捗 | `完了: T-0128「題」／ 成果物: path` |
| 転記 | 親 P の履歴 | `転記: P-0007「題」より（2026-08-20 21:00 以降の総括 3 件）` |
| 〃 | 自分の履歴 | `転記: P-0001「親」へ（2026-08-23 19:20 まで／1 件）` |
| 中止 | 当人 | `中止: 理由` |
| 読み替え | 当人 P の**意図** | `読み替え: 〈新しい読み〉（理由）`（§2「意図」） |

**追随だけは追記行ではなく `## 文脈` に書く**（§5）。文脈の変化は文脈の中で見えるべきなので。
**読み替えも同じ理由で `## 意図` に書く**（意図の変化は意図の中で見えるべき）。

## 4. 総括（project）とレポート（task）

**独立した節にしない。** 履歴・進捗の中に見出しとして置く。

**プロジェクトの総括は 5 枠**（v0.4）。

```
### 総括 2026-08-26 10:40
*（範囲: 2026-08-23 12:44 の総括 以降）*

**意図**
- この枝が何を問うて切られたか（原点の言い直し）。この期間で問いがどう読み替わったか
  （狭まった・広がった・別のものだと分かった）。積むほどではない揺れもここに
**経緯**
- 意図から決定に至った道筋。何を観測し、何が制約になり、どこに分かれ道があったか。時系列の散文。
  決定の番号を指す。**決定の羅列にしない**
**決定**
- 決めたこと ／ 理由 ／ 対象: path（経緯の何番目から出たかを添える）
**却下**
- 捨てた案 ／ 理由 ／ 再開条件
**未解決**
- まだ決まっていないこと。次の期間へ渡すもの
```

* **なぜ意図と経緯が要るか。** 総括は転記で**親の履歴**に載る —— 親はこの枝の意図も文脈も持たない。
  決定だけ運ぶと**決定の範囲**（どういう問いの下で、何を観測し、何を制約として決めたか）が届かず、
  範囲の無い規則が親の側で全体へ持ち出される。**意図＝問いの範囲、経緯＝決定が立っている観測と制約。**
  サブプロジェクトの子タスクのレポートは**サブプロジェクトの履歴に落ちて親には来ない**ので、
  決定・却下を親へ運ぶ経路は総括だけである
* **タスクのレポートは 3 枠**（決定・却下・未解決）。`### レポート 2026-08-23 17:00`。閉じるときに書く。
  意図・経緯が無い理由: レポートは**所属プロジェクトの中**で読まれ、読者は文脈を持つ。経緯は `## 進捗` にその場である。
  **非対称は「読者が文脈を持つか」**
* 根（親の無いプロジェクト）の総括も同じ 5 枠。読者は後継か未来の自分で、どちらも文脈を持たない側
* **枠の中へは後からも足せる。** 確認の場で未解決が解決したときなど。
  書式は **`- **追記 <日時> <名前>**: 本文`**（§0 の例外）。
  **ふつうの追記（`- <日時> …`）は枠を閉じる**ので、その形で書くと枠の外へ落ち、**親へ運ばれない**
* **タスクのレポートが親へ運ばれるのは `done` になった瞬間。**
  「確認へ回す」では運ばない —— **確認で分かったことを親に載せるため**である。運ぶのはちょうど一度だけ。
  **中止（`dropped`）では運ばない**（親に載せずに終わらせる道）
* **決定は 1 行で言い切る。**表が要るなら別ファイルに置き、ここからパスで指す
* **却下枠を省略しない。**成果物には採用した道しか残らないので、却下枠が無いと後日また同じ案を出す
* **総括が二度要るタスクは、タスクではない**（プロジェクトにすべきだった合図）
* 実装は枠を読まない（見出しと枠の終端だけを見て逐語で運ぶ）。枠の変更は記法・規律・手引きの話である

## 5. 文脈（project のみ）

```
## 文脈

### P-0045「Itera OS 本体の開発」より

#### 生成 2026-08-21 10:00（P-0045 を 2026-08-21 09:30 まで）

- （意図に照らして畳んだ本文）

#### 追随 2026-08-23 17:00（2026-08-23 16:00 まで）

- （差分を畳んだもの）
```

* **源ごとに `###` を立てる。**親に限らない（傍系から畳んでもよい）
* **畳む対象は、源の「意図・文脈・履歴」の全部。** 履歴だけでは足りない ——
  **源が知っていることは、その源の文脈にも入っている**（実例: P-0001 の履歴は 1 行で、中身は全部 文脈 にあった）
* **源は「札の id」でも「外の文書のパス」でもよい**（`### docs/blueprints/例.md「題」より`）。
  文脈は「**外の世界のうち、この枝に効くもの**」であって、必ずしも別のプロジェクトとは限らない。
  ただし**外の文書は Loom の履歴を持たないので、伸びたかどうかを機械では言えない** —— 古びは自分で見る
* **古びには 2 方向ある。** ①**源が伸びた**（取り込み点より後に履歴が積まれた。追随で受ける）／
  ②**観点が動いた**（自分の `## 意図` が読み替わった。写しは古い観点で畳まれている）。
  ②は取り込み点では見えない。**読み替えの行が印**である（§2「意図」）
* **取り込み点は「最後の `#### …（… まで）`」から導く。**front matter には持たない（二重管理を避ける）
* **追随は積むだけ**（書き換えゼロ）
* **再生成**（畳み直し）のときは `## 文脈` を丸ごと書き換えてよい。**写しだから**。
  ただし `## 履歴` に 1 行残す —— `再生成: P-0045 の文脈を畳み直した（前版は 2026-08-21 10:00 生成）`。
  読み替えを機に畳み直すなら、その行に読み替えの日時を添える

## 6. 転記の中身

親の履歴に入る形。**畳まない。子が書いた総括をそのまま載せる。**

**2 つの決まりがある**（どちらも実装して初めて必要と分かった。2026-08-23 / T-0082）。

* **渡した側は「どこまで渡したか」を書く**（`… まで／N 件`）。
  転記した**時刻**で覚えると、総括を後から書いたり時計がずれたりしただけで、
  二重送りや取りこぼしが起きる。**総括の時間軸どうしで比べること。**
  これは相手ではなく**自分の履歴の中の位置**なので、辺ではなく自分に付く
  （「座標系は源にあり、値は辺にある」の系）。
* **運ばれてきた総括には出どころを付ける**（`### 総括 <日時>（P-0002）`）。
  付けないと、**子の総括が親自身の総括として孫へ再び流れ**、根に子孫全部の総括が積み上がる。
  それは文脈で受けるはずだった肥大がそのまま起きるということ。**自分が書いた総括だけを上げる。**

```
- 2026-08-23 17:30 転記: P-0007「題」より（2026-08-20 21:00 以降の総括 2 件）

### 総括 2026-08-21 09:00（P-0007）
…
### 総括 2026-08-23 12:00（P-0007）
…
```

## 7. 迷ったときの判別

| 迷い | 判別 |
| :-- | :-- |
| 分岐か分解か | 増えたのが**知識・観点**なら分岐（P）、**仕事**なら分解（T） |
| 分岐か継承か | **前任が生き続けるなら分岐、役目を丸ごと引き受けて前任が終わるなら継承** |
| 意図が変わった。読み替えか継承か | **原点がまだ新しい読みを含む**（狭まった・広がった・研がれた）なら読み替え（`## 意図` に積む）。**原点を置き換えねばならない**（別の問い／文脈の大半を畳み直す／親の `分岐:` 行がこの枝を言い当てなくなる）なら継承。継承の引き金は **履歴の肥大**と**意図の置き換え**の 2 つ |
| 意図の読み替えに気づいたのが AI（畳む者）だった | **総括の「意図」枠に観測として書き、人に伝える。** `## 意図` へ積むのは人の一手 |
| タスクの子にプロジェクトを吊るしたい | **できない。**親は**そのタスクの所属プロジェクト**になる（タスクは通り道） |
| サブタスクの成果をプロジェクトへ上げたい | **上げない。**親タスクのレポートで畳まれて上がる（履歴の粒度のつまみ） |
| 子が全部閉じた。親タスクも閉じるか | **閉じない。**統合の一手が残る。親を閉じるとき開いた子は**プロジェクト直下へ繰り上げる** |
