# Loom — プロジェクトの系譜と、その下の仕事

**版 0.2（2026-08-24）。** 実体は `apps/loom.html`、データは `data/apps/loom/`（**1 ノード 1 ファイル**）。
記法の正は `docs/manual/loom_notation.md`、AI 側の動き方は `memory/rules/loom.md`。

> **何のための道具か。** 長く続く仕事を、あなたと AI が一緒に進めるための板です。
> **プロジェクトの系譜**が主役で、タスクはその下にぶら下がります。
> 知識はプロジェクトに、仕事はタスクに置きます（**タスクは終わるので、そこに置いた知識は失われます**）。
>
> **アプリを起動しなくても、ファイルを直接読み書きできます。** 唯一の正はファイルです。

---

## 1. 2 つの器

| | プロジェクト | タスク |
| :-- | :-- | :-- |
| 置くもの | **意図**（観点。満たされない） | **依頼**（完了条件。満たされる） |
| 増やす | **分岐**（子を切る） | **起票／分解** |
| 減らす | **終結（合流）** | **完了** |
| 終わるか | 終わらない（凍結・継承・放棄はある） | 終わる |
| 状態 | 生きている／凍結／継承済み／放棄 | 下書き→依頼済み→作業中→確認待ち→完了 |
| 手番 | **持たない** | 持つ（あなた／Itera） |
| 文脈 | **持つ** | **持たない**（所属プロジェクトの文脈を使う） |

**知識の置き場はプロジェクト。タスクは仕事の置き場です。**
タスクは閉じるので、そこに知識を置くと失われます。

## 2. 画面

* **左＝系譜。** プロジェクトの木で、その下にタスクが並びます。
  「タスク」「閉じたもの」で出し入れできます。ほかに「Iteraの番」「あなたの番」「今日」「閉じた」の平らな一覧。
* **枝の開閉は憶えます。** つまみ（`▸` / `▾`）で畳んだ状態は、次に開いたときも保たれます
  （記録は `data/apps/loom_ui.json`）。**初めて使うときは畳んだ状態から始まります。**
  「すべて閉じる」「すべて開く」で一気に戻せます。
  なお**選んだ札までの道は自動で開く**ので、畳んでいても見失いません
* **「全景」** は板そのものを数えて見る画面です。枚数・状態の分布・根と子孫の数のほかに、
  **ファイルの数と画面に出ている札の数が合っているか**を照合します。
  読めなかったファイル・画面に出ない札・id の重複・親が板に無い札が見つかると、赤い帯で出ます。
  何も出なければ「すべて読め、すべて画面から辿り着けます」と出るので、**そこだけ見れば足ります**。
* 札の右肩の印: **`→ n`** = 上流が伸びていて追随が要る ／ **`↑ n`** = 親へ渡していない総括がある
* **右＝詳細。** プロジェクトなら 意図・文脈・履歴・成果物、タスクなら 依頼・計画・追加要望・進捗・確認事項・成果物。

## 3. 操作

### プロジェクト

| ボタン | 何が起きるか |
| :-- | :-- |
| **分岐 ⑂** | 子プロジェクトを作る。**意図はあなたが書く**（それが圧縮の鍵になる） |
| **起票 ＋** | 下にタスクを立てる。履歴に 1 行残る |
| **継承 ⇥** | フェーズを切る。**前任を凍結し、後継を作る。子はそのまま後継が引き継ぐ** |
| **総括を頼む** | 区切りまでの 決定・却下・未解決 を Itera が書く |
| **転記 ↑** | **未送の総括を、畳まずそのまま親の履歴へ載せる** |
| **終結（合流）** | 転記して役目を終える。**一緒になるのは、この最後の一回だけ** |

### タスク

| ボタン | 何が起きるか |
| :-- | :-- |
| **分解 ⋔** | サブタスクに割る |
| **レポートを頼む** | 閉じる前に、Itera がレポート（決定・却下・未解決）を書く |
| **確認へ回す ✓** | レポートがあることを確かめて**確認待ち**にする。**この時点では親へ運びません** |
| **レポートに追記（解決など）** | 追記欄に書いて押すと、**レポートの枠の中**に 1 行足します |
| **確認したので完了にする（→ 親へ運ぶ）** | **運ぶのはここです。** レポートと成果物が所属プロジェクトの履歴へ、上位タスクへは 1 行だけ |
| **AI に渡す／中断／自分に戻す** | 手番の受け渡し |

#### 閉じるまでの流れ

```
Itera がレポートを書く → 「確認へ回す ✓」（確認待ち。まだ運ばない）
   → あなたが読む → 解決した未解決があれば「レポートに追記」
   → 「確認したので完了にする」→ このとき親へ運ばれる
```

**運ぶのを確認の後にしてあるのは、確認で分かったことを親に載せるためです。**
以前は「完了」と同時に運んでいたので、あなたが確認する時点では**すでに親へ載っており**、
そこで解決した未解決も、古いまま上流へ流れていました（2026-08-24 に直しました）。

* **追記はレポートの枠の中に入ります。** ふつうの追記（`- 日時 …`）は枠の外に落ちて親へ運ばれないので、
  解決を書き残すときは必ずこのボタンを使ってください
* **もう運ばれた後**に追記しようとすると警告が出ます。親の側は運ばれた時点の写しなので、
  あとから書いても**親には届きません**
* 二度運ばれることはありません（親の履歴に残る「完了: <id>」を証拠として見ています）

## 4. 文脈と、その古び

子プロジェクトは、親（や傍系）を**自分の意図で畳んだもの**を `## 文脈` に持ちます。
畳んだものは**写し**なので、源が伸びると古びます。

```
## 文脈
### P-0045「Itera OS 本体」より
#### 生成 2026-08-21 10:00（P-0045 を 2026-08-21 09:30 まで）
#### 追随 2026-08-23 17:00（2026-08-23 16:00 まで）
```

* **取り込み点は最後の「… まで」**です。画面の「文脈の取り込み点」欄に、源がどこまで伸びたかと並べて出ます
* 古びていたら **「追随を頼む」**（差分だけを追記）。肥大したら **「再生成を頼む」**（意図に照らして畳み直す）
* **畳むのは Itera の仕事です。**ボタンは依頼を送るだけで、要約文を機械が作ることはありません

## 5. 覚えておくとよい 3 つ

1. **転記は畳まない。** 親が読みにくくなったら、親を短くするのではなく**文脈で受ける**
2. **畳んだものだけが古びる。** だから時刻（取り込み点）が付くのは文脈だけ
3. **書き換えてよいのは写しだけ。** 文脈は畳み直してよい。**履歴・進捗は絶対に書き換えない**

## 6. 安全について

* 書き込みは必ず「**読み直す → 変換する → 書き込む**」を通ります（追記どうしは競合しません）
* **編集中に Itera が同じ札を更新したら、保存は中止して掲示を出します。**あなたの入力は消えません
  （基準は「**編集を始めた時点の本文**」です。ここを取り違えると、外部の追記を黙って踏み潰します —— 実際に一度踏みました）
* 他の札の更新では、**開いている画面に触れません**

## 7. まだ無いもの

* **傍系（接触通知）** … 直系（親子）以外の関連する枝は、自動では気づけません。
  必要なら手で「転記」先を親以外にします
* **文脈の畳み直しの時機** … 文脈が伸びすぎたときに畳み直す（再生成）操作はありますが、
  **いつ畳み直すべきかを機械が教えてくれるわけではありません**。読みにくいと感じたら頼んでください
* **AI からあなたへの通知** … 板を「質問待ち」にしても、あなたがこの画面を開かなければ気づけません。
  質問は板とチャットの両方に出すよう、AI 側の規律（`memory/rules/loom.md`）で決めてあります

## 8. 最初の一歩

1. **「＋ プロジェクト」で枝を切り、`## 意図` を書く。**
   意図は「なぜこの枝が在るのか」であり、**満たされて消えない文**です（例:「認証まわりを他から切り離して扱えるようにする」）。
   ここが以後すべての圧縮の基準になるので、**AI に書かせず、あなたが書いてください**
2. **「起票 ＋」で仕事を置く。** こちらは逆に**満たされる文**（例:「電話番号の入力を必須にする」）
3. あとは AI に渡す。着手前に枝を根まで読み、計画を書き、終わったら報告（決定・却下・未解決）を残します
